# 原産地別 対米関税比較 (`/tariff`) — 설계

작성 2026-08-12 · 대상 저장소 `logisight-jp`

> 이 문서는 작업자용 설계서라 한국어로 쓴다.
> 저장소 관례대로 **코드 주석과 화면 문구는 일본어**로 쓴다. 섞지 않는다.

---

## 1. 왜 이걸 만드는가

출발점은 「관세 + 운임 + 환율 = 엔화 착지 원가」였다. 측정하면서 세 번 모양이 바뀌었고,
그 과정이 곧 이 설계의 근거다. 지우면 같은 길을 다시 걷게 되므로 남긴다.

### 1-1. 세 재료는 단위가 다르다

| 재료 | 위치 | 형태 |
|---|---|---|
| 관세 | LandedIQ `rate_ledger` | 절대값 (%, USD) — **미국 수입** 기준 |
| 운임 | `jp_price_indices` (일본은행 SPPI) | 지수 (2020=100) |
| 환율 | 円ベース ÷ 契約通貨ベース | 비율 (이미 분해돼 있음) |

지수는 금액에 더할 수 없다. 절대 금액을 내려면 실제 운임 견적이 필요한데 사이트에 없다.
**따라서 금액은 내지 않는다.** 이 결정은 이후 모든 선택의 상위에 있다.

### 1-2. 수입 방향에는 관세를 넣을 이유가 없다

일본 수입 관세는 税関 実行関税率表·Web タリフ가 무료로 정확히 제공한다. 조회가 쉽다.
그리고 거의 움직이지 않는다 — MFN은 고정, EPA는 일정대로 내려간다.

같은 기간 운임·환율은 이렇게 움직였다 (外航貨物輸送, 실측):

```
              円ベース   契約通貨    차이
2025-06        153.0     117.0     +36.0
2026-06        233.8     160.8     +73.0
──────────────────────────────────────────
전년동월비    +52.8%    +37.4%    +15.4pt
```

엔으로 내는 외항 운임이 1년 새 +52.8%, 그중 약 29%가 운임이 아니라 엔이다.
`base_year`는 전 구간 2020으로 균일하다(리베이스 아님을 확인함).
운임 37pt·환율 15pt 옆에 연 0.1pt 수준의 관세를 놓으면 칸이 빈다.

### 1-3. 수출 방향은 품목 가중치를 만들 수 없다

`jp_trade_by_commodity`는 **概況品 10그룹**뿐이고, 이력이 **6개월**(2026-01~06)이다.

```
일본 → 미국 수출, 2026-06 (약 1.93조엔)
  72.2%  機械類及び輸送用機器   ← 한 칸에 몰려 있다
   7.0%  特殊取扱品
   6.5%  原料別製品
   6.2%  雑製品
   6.0%  化学製品
   나머지 5그룹 합계 1.9%
```

72%를 먹는 그룹 안에 자동차와 반도체 장비가 같이 있다. 이 위에서 낸 가중평균은
무엇을 뜻하는지 설명할 수 없다.

### 1-4. 일본산은 품목과 무관하게 세율이 같다

배포된 `hts-lookup`에 `origin=JP`로 13개 품목을 조회한 결과, **전부 12.5%**였다.
자동차·열연강판·소고기·스웨터·신발·알루미늄·반도체장비·공작기계 등.

원인은 일본에 걸린 프로그램이 `top_up_to_total` 방식이기 때문이다. MFN이 얼마든
합계 12.5%까지 채운다 (자동차 2.5+10.0, 반도체장비 0+12.5, 공작기계 4.2+8.3).

**상수의 가중평균은 그 상수다.** 바스켓·가중치·품목별 분해가 전부 성립하지 않는다.

### 1-5. 움직이는 축은 품목이 아니라 원산지다

같은 품목(8703.23 승용차), 원산지만 교체:

```
メキシコ   2.5%   MFN 2.5
ドイツ    10.0%   MFN 2.5 + 上限補正 7.5
日本      12.5%   MFN 2.5 + 上限補正 10.0
韓国      12.5%   MFN 2.5 + 上限補正 10.0
中国      40.0%   MFN 2.5 + 301リスト1 25.0 + 強制労働 12.5   ← 상한 없음
```

이것이 지금 일본 제조업이 실제로 앉아 고민하는 질문 —
**「같은 물건을 어디서 내보낼 것인가」** — 에 그대로 답한다.

무역통계 가중치도, 새 수집기도, 바스켓도 필요 없다. 품목 하나에 원산지 여러 개를
물으면 끝난다. LandedIQ의 `/hts` 페이지조차 원산지를 하나씩만 받으므로 겹치지 않는다.

## 2. 범위

### 만드는 것

- `/tariff` 페이지 하나. 품목 1개 × 원산지 6개(로그인 시 최대 8개)의 미국 관세 비교.
- 품목 사전 (일본어 → HS 접두 22개) + 칩 입력.
- 다중 매칭일 때 줄을 고르는 후보 목록.
- 서버 함수 하나 (`getOriginComparison`).
- 캐시 테이블 하나 (`jp_tariff_cache`).
- 계약·불변식·스냅샷 테스트.

### 만들지 않는 것 — 그리고 그 이유

| 항목 | 이유 |
|---|---|
| 금액·수량 입력 | §1-1. 금액을 내지 않는다 |
| 품목 저장·감시 목록 | 테이블이 하나 더 든다. 링크 공유로 갈음된다 |
| 과거 시점(`as_of`) 조회 UI | v1은 오늘만. 키에는 미리 넣어둔다 |
| 원산지별 운임 칸 | SPPI는 **일본이 지불하는** 운임이라 「베트남 → 미국」을 모른다 |
| 관세 계산기 | LandedIQ가 한다. 링크만 건다 |
| 세율 변동 알림 메일 | CI 스냅샷이 먼저 돌아간 다음에 볼 일 |
| 품목 바스켓·가중 지수 | §1-4에서 성립하지 않음이 확인됨 |

## 3. 화면

이름: **`/tariff` — 原産地別 対米関税比較**
부제: 同じ品目を、どこから出すか。

```
┌──────────────────────────────────────────────────────┐
│ 品目  [ 8703.23  または  乗用車        ]   [ 調べる ] │
└──────────────────────────────────────────────────────┘

8703.23.01.10  乗用車(ガソリン 1.5〜3.0L)

  原産地      関税      内訳
  ─────────────────────────────────────────────
  メキシコ     2.5%     MFN 2.5
  ドイツ      10.0%     MFN 2.5 + 上限補正 7.5
  日本        12.5%     MFN 2.5 + 上限補正 10.0
  韓国        12.5%     MFN 2.5 + 上限補正 10.0
  ベトナム    12.5%     MFN 2.5 + 上限補正 10.0
  中国        40.0%     MFN 2.5 + 301リスト1 25.0 + 強制労働 12.5
  ─────────────────────────────────────────────
  日本 → 中国 との差   -27.5pt

  ※ 原資料 2026-07-29 時点。見積ではない。
```

- 기본 원산지 6개 고정: 日本·中国·ベトナム·タイ·メキシコ·韓国.
  일본 제조업이 실제로 검토하는 이전 후보다.
- 로그인 사용자는 원산지를 직접 고를 수 있다. **최대 8개**로 막는다 —
  원산지 1개가 곧 LandedIQ 호출 1회라, 상한이 없으면 한 사람이 분당 제한을 다 쓴다.
  저장 기능은 v1에 넣지 않는다(테이블이 하나 더 필요하고, 없어도 링크 공유로 갈음된다).
- 비로그인은 고정 6개. SEO와 유입을 위해 표 자체는 공개한다.

### 입력 — 일본어 키워드는 통하지 않는다

실제로 확인했다. 원장 설명문이 영어라서 이렇게 갈린다.

```
"8703.23"        → 7건    코드는 된다
"8703230110"     → 1건    10자리는 정확히 한 줄
"motor car"      → 20건   영어 키워드는 된다
"乗用車"          → 0건    ← 일본어는 안 된다
"passenger car"  → 0건    ← 영어도 구절이 안 맞으면 0
```

일본어 사용자가 미국 HTS 코드를 외우고 있을 리 없으므로, **품목 사전**을 둔다.

`src/lib/api/hs-dictionary.ts` 에 「일본어 품목명 → HS 접두」 22개를 담는다.
전부 실제 조회로 결과가 나오는 것만 넣었다(乗用車 8703.23, 半導体製造装置 8486.20,
油圧ショベル 8429.52, ベアリング 8482.10 …). 대미 수출의 72%가 機械類及び輸送用機器
한 그룹에 몰려 있으므로(§1-3), 22개로 실무 대부분이 덮인다.

입력 처리 순서:

```
1. 숫자 4자리 이상        → 코드 조회
2. 품목 사전에 있으면      → 그 HS 접두로 코드 조회
3. ASCII 문자열이면        → 영어 키워드로 그대로 넘긴다
4. 그 밖(일본어 미등록)    → 「品目名が見つかりません」 + 사전을 칩으로 보여준다
```

4번의 칩은 예비 수단이 아니라 **주 입력 수단**이다. 대부분의 이용자는 타이핑하지 않고
「乗用車」를 누른다.

### 조회 결과가 여러 줄일 때

10자리 코드는 한 줄로 확정된다. 그 밖(접두·키워드)은 여러 줄이 나오므로
**후보 목록을 먼저 보여주고 사용자가 한 줄을 고른다.** 임의로 첫 줄을 쓰지 않는다 —
8703.23만 해도 7줄이고 첫 줄은 「Motor homes」(캠핑카)다. 어느 줄을 봤는지 모르면
표 전체가 무의미해진다.

### 기준일

v1은 **오늘 날짜만** 쓴다. 화면에 날짜 입력을 두지 않는다.
다만 `as_of`는 캐시 키와 LandedIQ 요청에 처음부터 넣는다 — 나중에 과거 시점 비교를
붙일 때 캐시를 갈아엎지 않기 위해서다.
- 운임은 표 아래 문맥 한 줄로만 둔다:

  > 参考 — 日本発の海上運賃は円ベースで前年比 +52.8%(契約通貨 +37.4%)。
  > 原産地を変えれば運賃も変わるが、本表は関税のみを比べている。

## 4. 데이터 흐름

```
브라우저 ──▶ /tariff (TanStack Start route)
                │
                ├─ createServerFn  getOriginComparison({ q, origins, asOf })
                │     ├─ jp_tariff_cache 조회 (q_norm, origin, as_of)
                │     └─ 미스인 것만 ──▶ LandedIQ /functions/v1/hts-lookup
                │                          (원산지 1개당 1회)
                │
                └─ SPPI 한 줄 ── 기존 jp_price_indices
```

### 왜 서버에서 부르는가

브라우저에서 직접 부르면 LandedIQ 키가 페이지 소스에 노출되고 캐시도 못 한다.

대신 대가가 있다. **LandedIQ는 IP당 분당 30회 제한**이다. 서버에서 부르면 사이트
전체가 IP 하나로 보이므로, 원산지 6개 × 조회 5건이면 1분 만에 걸린다.
**캐시는 성능 최적화가 아니라 동작 조건이다.**

### 구성 파일

| 파일 | 역할 |
|---|---|
| `src/routes/tariff.tsx` | 라우트·SEO·`validateSearch` |
| `src/components/tariff/OriginTable.tsx` | 표 렌더 |
| `src/lib/api/tariff.ts` | 타입·정규화·**LandedIQ 응답 계약을 여기 한 곳에** |
| `src/lib/api/tariff.functions.ts` | `getOriginComparison` 서버 함수 |
| `supabase/migrations/*_jp_tariff_cache.sql` | 캐시 테이블 |

LandedIQ 응답을 다루는 코드는 `tariff.ts` 밖으로 새지 않게 한다. 남의 API가 바뀔 때
고칠 곳이 한 군데여야 한다.

### 환경변수

`LANDEDIQ_SUPABASE_URL`, `LANDEDIQ_ANON_KEY`. 서버 전용이므로 `VITE_` 접두를 붙이지 않는다.

## 5. 캐시

두 겹.

```
① CDN (PUBLIC_SWR_CACHE)      기존 서버함수와 같은 헤더. 반복 트래픽은 여기서 끝난다.
② jp_tariff_cache (Supabase)  (q_norm, origin, as_of) → 응답 JSON. 인스턴스가 갈려도 남는다.
```

②가 분당 30회를 실제로 막아주는 층이다. CDN 캐시는 리전마다 따로 데워지고 배포하면 날아간다.

- TTL **24시간**. 세율은 발효일에 바뀌지 시시각각 바뀌지 않는다.
- `q_norm` = 코드는 숫자만 남기고, 키워드는 소문자·공백 축약.
- 행에 `fetched_at`을 남기고 화면에 그 날짜를 표시한다.

### 부수 효과 — 의존 리스크 완화

이 테이블이 있으면 LandedIQ가 멈춰도 마지막 값으로 계속 보여줄 수 있다.
「LandedIQ가 멈추면 같이 멈춘다」가 「같이 멈추지는 않고, 대신 늙는다」가 된다.
그래서 **TTL이 지난 행도 지우지 않는다.** 오래됐음을 표시하고 쓴다.

## 6. 실패 처리

| 상황 | 화면 |
|---|---|
| 응답 없음·500 | 그 행만 「取得できず」. 다른 원산지는 그대로 |
| 429 제한 | 캐시값 + 시점 표시. 캐시도 없으면 「混み合っています」 |
| 품목 없음 | 「該当する品目が見つかりません」 + 품목 사전 칩 노출 |
| 일본어 미등록어 | 위와 같음. 일본어를 영어로 옮기려 시도하지 않는다 |
| 従量税·복합세 라인 | 「従量税のため本表では比較できない」 |

**빈칸을 0%로 메우지 않는다.** 관세가 없다는 것과 못 받아왔다는 것은 다른 말이다.
`hts_lines` 19,831행 중 2,198행이 종량세·복합세라 이 경로는 반드시 밟힌다.

### 경고를 삼키지 않는다

LandedIQ는 면제 판정을 3값으로 낸다 — 없음 / 확인됨 / **미확인**.
미확인은 「전액 부과 + 경고」다. 과소계상이 과대계상보다 손해가 크기 때문이고, 옳은 판단이다.

숫자만 꺼내고 경고를 버리면 남이 만든 3값을 1값 거짓말로 바꾸는 셈이다.
**경고는 숫자 옆에 그대로 표시한다.**

## 7. 테스트

세율은 **바뀌는 게 정상**이다. 그게 이 제품의 존재 이유다.
「12.5%인지 확인」하는 테스트를 짜면 정책이 바뀔 때마다 헛되이 빨개진다. 세 층으로 나눈다.

| 층 | 내용 | 깨지면 |
|---|---|---|
| ① 응답 형태 | `results[].code` / `duty_rate_total` / `programs[].code·rate` | 실패 — 남의 API가 조용히 바뀐 것 |
| ② 불변식 | 합계 = MFN + Σ프로그램(상한보정 반영) · 0 ≤ 세율 ≤ 1 · 같은 상한 그룹은 서로 같다 | 실패 |
| ③ 값 스냅샷 | 현재 세율을 커밋해두고 비교 | 실패 — 단, **버그가 아니라 뉴스** |

③의 실패 메시지는 이렇게 쓴다:

```
세율이 바뀌었다. 사실이면 스냅샷을 갱신하라.
  8703.23 / JP   12.5% → 15.0%
```

**세율 변화는 그달 리포트 소재다.** CI가 빨개지면 사람이 확인하러 오고, 확인하면 기사가 된다.
조용한 알림은 아무도 안 본다. 그래서 일부러 실패로 둔다.

①②는 실제 API를 부르므로 네트워크가 필요하다. 오프라인·CI 불안정에 대비해
저장된 응답 픽스처로도 돌 수 있게 한다. ③만 실제 호출을 요구한다.

## 8. 법정 표시

화면 하단에 일본어로 고정 표시한다.

```
本表は推計であり、通関・法務・税務の助言ではない。
従量税・複合税、アンチダンピング税、数量割当、および未確認の除外は含まない。
最終的な品目分類と納税義務は輸入者(Importer of Record)に帰属する。
関税率は LandedIQ が維持する原簿にもとづく。
```

## 9. 알려진 한계

정직하게 남긴다. 나중에 「왜 안 했지」를 다시 묻지 않기 위해서다.

1. **원산지별 운임을 모른다.** SPPI는 일본 지불 운임이다. 조달처를 옮기면 운임도
   바뀌지만 이 표는 관세만 비교한다. 화면에 그렇게 쓴다.
2. **LandedIQ 원장의 신선도에 종속된다.** 수집이 손으로 도는 npm 스크립트라
   안 돌리면 조용히 늙는다. 화면의 시점 표시가 유일한 방어선이다.
3. **일본산은 현재 모든 품목이 12.5%다.** 상한 보정이 걷히면 품목별로 갈릴 수 있고,
   그때는 §1-4의 결론이 바뀐다. 스냅샷 테스트가 그 순간을 잡아준다.
4. **종량세 품목은 비교 불가.** 전체 라인의 약 11%.
5. **품목 사전이 22개뿐이다.** 대미 수출 주력은 덮지만 전부는 아니다. 밖의 품목은
   코드를 직접 넣어야 한다. 사전을 늘리는 건 파일 한 줄 추가라 부담이 없으니,
   문의가 들어오는 대로 늘린다. 일본어를 기계 번역해 검색하는 길은 택하지 않는다 —
   틀린 품목에 맞는 세율을 보여주는 게 결과가 안 나오는 것보다 나쁘다.
